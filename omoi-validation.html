質問データの自動検証

node tools/verify-question-dataset.mjs --enforce-quality-targets --summary

Omoiリポジトリで実行します。4つのJSONを一つのデータセットとして読み、JSON構造、ID一意性、正規化した問いの完全重複、Levelと配置、必須metadata、12カテゴリ、視点、警告値、出典の形式を確認します。品質目標はLevel 2が80件以上、Level 4のaffected・actor・decision_makerがそれぞれ20%以上です。

2026年10月16日に、公開元の main / fe24acc と公開サイトを照合しました。以下の件数は、この版の質問JSONに基づきます。

この結果は、この版のデータ検証の結果です。文章の中立性、事実の正確さ、ブラウザ操作の成功を保証するものではありません。

画面と静的サイトの確認

Omoi本体にはビルド工程がありません。ソース変更時は該当JavaScriptの構文と画面フローを確認します。既存の確認用コマンドは次のとおりです。

node --check select.js
node --check question.js
node --check warning.js
node --check warning3.js
node --test tools/question-flow.test.mjs tools/level-warning-flow.test.mjs
node tools/verify-seo.mjs

この公式サイトのリンク・アンカー・見出し・製品別ナビゲーションは、公式サイトリポジトリでpython3 tools/check-site.pyを実行して確認します。データ検証と画面検証は、それぞれ結果を記録します。

ブラウザで確認する流れ

  1. 4カテゴリから一つを選ぶまで「次へ」が無効なことを確認します。カテゴリ3・4では開始前の案内を確認します。
  2. 選択したカテゴリのJSONを読み込み、場面文・問いが表示されることを確認します。補助情報があるときだけヒント・背景のボタンを表示します。
  3. 「次の問いを見る」で進み、「前の問い」で同じ問いへ戻れることを確認します。話さず進む場合も回答入力は求めません。
  4. ヒントと背景の開閉、用語と出典、Escape操作、長文のスクロールを確認します。
  5. 「ここで終える」の確認で「続ける」と「終了する」を試し、終了確定でホームへ戻ることを確認します。
  6. 質問カタログで検索・各フィルタ・追加表示を確認します。

公式カタログへの同期

公開元mainの特定commitを記録し、Omoiの4つのJSONをassets/omoi/dataへそのまま同期します。未公開のBetaやローカル編集を、公開中の製品仕様として扱わないようにします。

内容正本と同梱JSONをバイト単位で比較し、件数・ID・順序・任意フィールドを維持
表示場面文・会話のヒント・背景・用語・出典のあるカードをカタログで確認
集計Level別・上位カテゴリ別・視点別・警告別の集計と資料を同じ版に揃える
参照情報反映日・参照ブランチ・commit・件数・ライセンスをカタログへ表示
キャッシュJSONとカタログJavaScriptのバージョンを更新

公開前後の確認

  • git diff --checkと公式サイトのリンク検査が成功する
  • 正本のデータ検証結果と、同梱JSONの一致を確認する
  • 変更したJavaScriptの構文を確認する
  • デスクトップとモバイル幅で、Home・Projects・変更した資料とカタログを確認する
  • 公開操作後はGitHub Pagesがbuiltとなり、対象commitを配信していることを確認する
  • 公開URLの件数・参照commit・キャッシュ版が変更内容と一致することを確認する

ローカルでの確認だけでは、公開反映の完了にはなりません。

検証に失敗した場合

原因をデータ、表示、操作、配信に分けて確認します。失敗を通すために質問を隠したり機能を削除したりせず、既存の警告や別作業の変更も記録して修正します。
